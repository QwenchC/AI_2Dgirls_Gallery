# 验证说明

本项目分别检查内容完整性、页面功能与发布内容。文本模板和格式正确，不代表模型生成质量已经验证。

## 内容完整性

运行 `node scripts/verify.mjs` 可检查：

- 14 个角色、每角色三种体型、共 42 张原图与 42 张预览。
- 图像与 `data/original-images.json` 中的 SHA-256 基线一致。
- JSON 数据与供离线页面加载的脚本数据一致。
- 角色来源引用与本地文档链接完整。
- 页面没有初始远程脚本、远程字体或在线数据依赖。

默认只向终端输出结果；使用 `--write-report` 可将结果写入被 Git 忽略的 `artifacts/` 目录。不要提交运行日志、下载样本或环境诊断记录。

## 页面功能

页面功能检查应覆盖三体型切换、搜索与空结果、14 张角色卡、来源页签、键盘导航、关闭弹窗后的焦点恢复、角色带入工坊、简报编辑、复制与下载，以及宽屏和窄屏布局。

页面采用无需服务器端代码的静态资源结构。不同浏览器对直接打开 HTML、剪贴板和下载的支持可能不同；请在计划使用的浏览器中复核。必要时可以通过自己选择的静态文件服务器浏览。

## 发布内容检查

运行 `python scripts/check_privacy.py` 检查待发布目录；Git 暂存后运行 `python scripts/check_privacy.py --staged` 直接检查暂存对象。检查包括个人绝对路径、环境与凭据文件、常见密钥模式、图像嵌入文本及 EXIF/XMP 元数据等。

扫描只报告相对文件名与问题类别，不回显匹配内容。自动扫描是辅助措施，发布前仍需人工复核新增文档、图片和提交清单。代码示例只应使用仓库相对路径与通用参数；提交身份宜采用 GitHub 用户名与 GitHub noreply 邮箱。

## 生成示例与研究边界

- H3 文档是基于公开上游资料的通用教程，不是设备环境记录。
- 仓库辅助 Skill 和 Ref2VA 示例属于文本策划，未附带生成质量保证。
- 更上游图像来源、部分角色完整设定与无法直接读取的原帖仍需进一步考证；各资料保留了对应证据范围。
